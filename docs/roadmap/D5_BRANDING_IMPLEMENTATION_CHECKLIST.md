## 2. Needs its own decision (not part of the visible rename)

- **Model-facing text:** the Copilot system prompt (`src/copilot/agent.ts`, lines naming "Atlas") and the tool descriptions in `src/copilot/tools.ts` and `demo.ts` mention "Atlas". These are the runtime prompt and tools, which must not change in a branding pass; they also feed the evaluation cases. Rename them only if the owner decides to, as a separate change with the evaluation baselines in view. Until then the model may still call the product "Atlas" in answers, which should be disclosed in the branding PR.
- **The credential-store service name:** `KEYCHAIN_SERVICE = "Atlas Proposal Engine"` in `src/copilot/credentialStore.ts` is the key under which the operating system stores a remembered key. Changing it would orphan any remembered key. A rename needs a migration (read the old entry, write the new, delete the old) and its own review. **Leave unchanged by default.**

## 4. Verification before and after

1. **Before editing:** list every changed string and confirm it is in section 1. Post a short impact note on the branding PR.
2. **Saved workspace:** restore an existing saved workspace (including a v6 saved one and a v10 backup) and confirm it loads with identical data (compare the stored JSON hash).
3. **Routes and links:** every page route and the PDF route work; the old production URL still serves.
4. **PDF and meeting view:** render a draft and a final from an approved version; read the product-name lines and the disclaimers.
5. **Local mode:** `npm run local:doctor` and the connect/pairing path still work (fake provider only), with the updated messages.
6. **Tests:** typecheck, full tests, extraction eval and build; update only the display-text assertions that the rename changes.
7. **Browser:** title, sidebar, one page, the PDF Preview and a keyboard pass at a narrow viewport. No console errors.
